● 진행중 · 2026.03 – 현재 (5개월+)

레거시 화면 자동 변환 시스템 구축 (MyBuilder → Nexacro)

레거시 MyBuilder 화면을 Nexacro(XFDL)로 옮기는 작업을 Claude Code에게 반복시키기 위해 만든 개인 프로젝트입니다. 변환 규칙을 사람이 읽는 문서가 아니라 AI가 조회할 수 있는 YAML 카탈로그로 만들고, 변환·검증 절차를 Skill로 고정했습니다. 원본 코드에서 다섯 축(이벤트 핸들러·인라인 SQL·검증 분기·SELECT 명세·콤보 소스)을 스크립트로 뽑아 산출물과 1:1로 대조하는 방식으로, 사람이 놓치기 쉬운 누락을 기계가 세도록 만든 게 핵심입니다.

5단계 진화 과정

01
산문으로 시작

변환 표준을 사람이 읽는 문서로 작성. 규칙이 늘수록 매번 전체를 읽어야 하는 한계에 부딪힘.

03.31–04.16
02
규칙을 카탈로그로 전환

산문을 원자 단위 YAML로 쪼개고, 검증 스크립트를 같은 날 붙여 카탈로그가 깨지지 않게 함.

04.22–04.30
03
전수 분석과 측정

벤더 납품 화면 2개를 기준(gold)으로 전수 분석하고, 새 세션에서 기준코드 없이 재변환해 매칭률 87%를 확인. 카탈로그가 기준코드의 버그 2건을 자동 회피하는 것도 발견.

04.24–04.27
04
절차를 Skill로 고정

역할 문서·프롬프트 모음을 폐기하고 Claude Code Skill로 이관, 호출 트리거 문구까지 명문화.

04.30–05.15
05
거버넌스 도입

변환 화면이 100개에 가까워지며 생긴 문제는 규칙이 아니라 규칙 관리였음. 파일 수명 규약과 인계선을 정의.

08.21–09.03

잘 되고 있는지 측정하는 3가지 방법

안정화 측정

새 세션에서 기준코드를 참조하지 않고 이미 변환한 화면을 다시 변환해 매칭률을 잰다 → 종합 87%, 4화면 중 3화면이 80% 이상.

예시 커버리지

매칭률이 낮은 영역이 어디인지 본다 → 명시 예시가 없는 영역에서만 크게 흔들림. 규칙 문장보다 예시가 힘이 셈.

기준 역전

산출물이 기준코드와 다를 때 어느 쪽이 맞는지 본다 → 카탈로그가 기준코드의 버그를 자동 회피하기 시작하면, 그때부터 카탈로그가 더 신뢰할 만한 기준이 됨.

처음부터 넣었어야 할 7가지 원칙

A
기준 코퍼스는 하나만

벤더 납품 코드에서 2개 이상 화면으로 재확인될 때만 표준으로 승격한다.

B
규칙은 원자 단위로

엔트리 하나 = 규칙 하나. 산문으로 되돌아가는 순간 카탈로그는 무너진다.

C
절차는 Skill로, 부르는 말까지

절차·처방·횡단 규칙을 한 곳에만 두고, 트리거 문구까지 명문화한다.

D
누락은 스크립트가 센다

사람이 "빠짐없이 봤나"를 기억으로 답하게 하지 않는다. 카운트로 답하게 한다.

E
착수 전 게이트

입력이 다 확보됐는지 기계가 먼저 판정하고, 없으면 시작하지 않는다.

F
파일 수명을 이름에

불변·재생성·가변을 파일명 규약으로 구분해 검사기가 강제하게 한다.

G
인계선은 시점으로

푸시가 인계선이다. 그 이후 AI는 결함을 발견해도 보고까지만 한다.
