레거시 화면 자동 변환 시스템 구축 (MyBuilder → Nexacro)

경운대학교 학사 시스템의 MyBuilder 화면을 Nexacro(XFDL)로 옮기는 작업을 Claude Code에게 반복시키기 위해 만든 저장소입니다. 160일 동안 바뀐 것은 화면 수만이 아니라 일하는 방식의 세 축이었습니다 — 작업을 거는 말(270줄 프롬프트 → 화면 ID 한 줄), 규칙을 두는 곳(한국어 산문 → 기계가 읽는 YAML), 누락을 잡는 것(사람 눈 → 파이썬 검사 게이트).

한 화면을 옮긴다는 것

원본 · mvf

벤더가 넘긴 MyBuilder 화면 정의(XML). 이벤트 핸들러·인라인 SQL·검증 분기·콤보 소스가 한 파일에 섞여 있는, 유일한 기능 명세입니다.

화면 · xfdl

Nexacro 화면 파일입니다. 레이아웃의 권위는 원본이 아니라 협력사가 미리 만든 baseline 이 갖습니다.

백엔드 4종

Controller · Service · ServiceImpl · Mapper. 원본의 인라인 SQL 을 MyBatis Mapper 로 내리되, SELECT 와 WHERE 는 전 라인 그대로 옮깁니다.

기록 · 검수

회차마다 남기는 불변 기록(001-*.md)과, 원본에서 기계가 뽑은 목록으로 만든 실행형 체크리스트(scenario.html). 코드만 만들고 기록을 빼면 변환이 끝난 것이 아닙니다.

두 기준선. 로직·SQL 의 기준은 원본 mvf, UI 의 기준은 협력사 baseline 입니다. 원본이 비효율적으로 보여도 임의로 고치지 않고 먼저 보고합니다. baseline 이 없으면(101화면 중 51) 설계 캡처가 UI 기준을 대신하고, 캡처마저 없으면 작업을 멈추고 사람에게 묻습니다.

기능 추가 예시

규칙을 문서에 적어 두는 것만으로는 AI 가 늘 지키지 않습니다. 이 부는 반대 방향입니다 — 도구 자체를 늘려서, 매번 말하지 않아도 되게 만드는 방법입니다. “토큰이 얼마나 남았지?” 를 매번 묻지 않고 늘 보이게 하는 것, “demo_001 끝났습니다” 를 사람이 선언하지 않아도 나오게 하는 것이 여기 속합니다. 여기서 늘리는 스킬은 AI 도구를 내 일에 맞게 고쳐 쓰는 법입니다.

이 부를 읽는 방법

아래 예시는 전부 2부의 연습 폴더($root)에 붙이는 모양으로 적었습니다. 그래서 경로가 사람마다 달라지지 않습니다.

스크립트는 2026-09-10 에 Windows PowerShell 5.1 에서 실제로 돌려 본 것이고, 훅 이름과 JSON 필드는 같은 날 Claude Code 공식 문서와 대조한 값입니다. 화면에 “정상일 때 나오는 것” 으로 적힌 것도 전부 그때의 실제 출력입니다.

1.1확장 지점은 여섯 곳입니다

CLAUDE.md 와 스킬은 모두 AI 에게 무엇을 시킬지를 정하는 장치입니다. 그 바깥에 사람이 말하지 않아도 돌아가는 자리가 여섯 곳 있습니다.

① 스킬 · 슬래시 커맨드 — 말하면 절차가 걸린다
.claude\skills\<이름>\SKILL.md 로 두면 /<이름> 으로도, 그냥 말로도 부를 수 있습니다. .claude\commands\<이름>.md 도 동작은 같지만, 스킬만 보조 파일을 함께 둘 수 있어 새로 만들 때는 스킬 쪽을 권합니다. 서브에이전트(④)까지 셋은 만드는 방법이 같습니다 — 바로 아래 표가 그 순서입니다.
② 훅(hooks) — 말하지 않아도 정해진 시점에 돌아간다
settings.json 의 hooks 에 등록해 두면 세션 시작 · 도구 사용 전후 · 턴 종료 같은 시점에 지정한 명령이 자동으로 실행됩니다. 이 부의 예시 대부분이 훅입니다. “내가 따로 선언하지 않아도 늘 나오게 하고 싶다” 는 요구는 거의 전부 훅으로 풀립니다.
③ 상태줄(statusLine) — 늘 보인다
화면 아래에 한 줄로 붙는 계기판입니다. 스크립트 하나를 지정하면 Claude Code 가 세션 정보를 JSON 으로 넣어 주고, 스크립트가 출력한 한 줄이 그대로 표시됩니다. 컨텍스트 잔량 · 비용 · 현재 폴더를 여기에 걸어 둡니다.
④ 서브에이전트 — 여러 갈래를 동시에 훑는다
.claude\agents\<이름>.md 로 역할을 고정해 둡니다. “화면 백 개를 훑어 이 패턴이 어디에 있는지” 같은 넓게 읽고 결론만 가져오는 일에 씁니다.
⑤ MCP 서버 — 없는 도구를 만들어 붙인다
Claude Code 가 못 하는 일(브라우저 조작, 사내 시스템 조회 등)을 외부 프로그램으로 붙이는 규격입니다. .mcp.json 에 서버를 적으면 그 서버의 기능이 AI 가 부를 수 있는 도구로 늘어납니다.
⑥ 플러그인 — 위의 묶음을 다른 PC 에 그대로
스킬 · 훅 · MCP 설정을 한 덩어리로 묶어 다른 PC 에 똑같이 설치하는 방법입니다. /plugin 으로 설치합니다(1.9).
“파일만 두면 걸리는” 셋 — 실제로 치는 순서

위 여섯 중 ①(스킬 · 슬래시 커맨드) 과 ④(서브에이전트), 이 셋은 설정 등록이 필요 없습니다. 정해진 폴더에 .md 파일 하나를 두면 Claude Code 가 켜질 때 폴더를 훑어 스스로 찾습니다. 그래서 셋 다 만드는 순서가 완전히 같습니다 — 폴더 이름만 다릅니다.

1 · 만들기
스크립트 파일을 만듭니다
일반 PowerShell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude" | Out-Null

첫 줄은 아무것도 출력되지 않는 것이 정상입니다(| Out-Null 이 출력을 버립니다). 둘째 줄에서 메모장이 열리며 “파일을 찾을 수 없습니다. 새 파일을 만들겠습니까?” 라고 물으면 예. 붙여넣을 본문 전체는 1.3 에 있습니다.

저장할 때 무엇을 입력하는가

여기서 따로 입력할 것은 없습니다. 파일 경로와 이름을 이미 notepad 뒤에 적어 주었기 때문에, 붙여넣고 Ctrl+S 만 누르면 끝입니다 — 파일 이름을 다시 묻지 않습니다.

딱 하나 확인할 것은 인코딩입니다. 스크립트에 한글 주석이 들어 있으므로, 메모장 저장 대화상자 (Ctrl+Shift+S) 아래쪽 인코딩 목록에서 BOM 이 붙은 UTF-8 을 고릅니다 — Windows 10 은 UTF-8(BOM), Windows 11 은 UTF-8 with BOM. Windows 에 들어 있는 PowerShell 5.1 은 BOM 이 없으면 한글을 ANSI 로 잘못 읽습니다.

저장한 뒤 PowerShell 로 돌아와 첫 3바이트를 확인합니다.

일반 PowerShell
$p = "$env:USERPROFILE\.claude\statusline.ps1"
(Get-Content $p -Encoding Byte -TotalCount 3 | ForEach-Object { '{0:X2}' -f $_ }) -join ' '
정상일 때 나오는 것
EF BB BF

다른 값이 나왔으면 메모장을 다시 열 필요 없이 한 줄로 고칩니다.

일반 PowerShell · 내용은 그대로 두고 UTF-8(BOM) 으로 다시 저장
[IO.File]::WriteAllText($p, [IO.File]::ReadAllText($p), (New-Object Text.UTF8Encoding $true))
이 파일 안에서 ‘사용률’ 과 ‘잔량’ 을 꺼내는 자리

두 숫자를 꺼내는 것은 이 네 줄이 전부입니다 — 굵게 표시된 곳이 바꾸면 달라지는 자리이고, 나머지는 보기 좋게 다듬는 부분입니다.

statusline.ps1 중에서
$used = 0
if ($null -ne $j.context_window.used_percentage) { … }        # ← 사용률

$left = 100 - $used
if ($null -ne $j.context_window.remaining_percentage) { … }   # ← 잔량

둘 중 하나만 써도 됩니다 — 더하면 100 이기 때문입니다. 그럼에도 둘 다 꺼내는 것은 Claude Code 가 둘 중 하나만 보내 주는 경우가 있기 때문입니다. $left = 100 - $used 를 먼저 깔아 두고 remaining_percentage 가 있을 때만 덮어쓰는 순서가 그 대비입니다.

2 · 시험
Claude Code 없이 먼저 돌려 봅니다

이 단계를 건너뛰면 나중에 “안 뜨는데 어디가 문제인지” 를 알 수 없습니다. Claude Code 가 넣어 줄 JSON 을 사람이 손으로 똑같이 만들어 넣어 봅니다 — 공식 문서도 이 순서를 권합니다.

일반 PowerShell
$s  = "$env:USERPROFILE\.claude\statusline.ps1"
$m1 = '{"model":{"display_name":"Opus"},"workspace":{"current_dir":"C:\\work\\claudeCodeSampleSyw"},"context_window":{"used_percentage":27,"remaining_percentage":73},"cost":{"total_cost_usd":1.234}}'
$m2 = '{"model":{"display_name":"Opus"},"workspace":{"current_dir":"C:\\work\\claudeCodeSampleSyw"},"context_window":{"used_percentage":85,"remaining_percentage":15},"cost":{"total_cost_usd":12.5}}'
$m3 = '{"model":{"display_name":"Opus"},"workspace":{"current_dir":"C:\\work\\claudeCodeSampleSyw"},"context_window":null,"cost":{"total_cost_usd":0}}'

$m1 | powershell -NoProfile -ExecutionPolicy Bypass -File $s   # 시험 1 : 세션 중반
$m2 | powershell -NoProfile -ExecutionPolicy Bypass -File $s   # 시험 2 : 잔량 얇음
$m3 | powershell -NoProfile -ExecutionPolicy Bypass -File $s   # 시험 3 : 세션 첫 응답 전 (null)
정상일 때 나오는 것 — 2026-09-10 실측
--- 시험 1 : 세션 중반 (used 27 / remaining 73) ---
[Opus] claudeCodeSampleSyw | [###-------] 사용 27% / 남음 73% | USD 1.23

--- 시험 2 : 잔량 얇음 (used 85 / remaining 15) ---
[Opus] claudeCodeSampleSyw | [########--] 사용 85% / 남음 15% !! | USD 12.50

--- 시험 3 : 세션 첫 응답 전 (context_window 가 null) ---

세 경우를 다 시험하는 것이 요점입니다. 1 은 평상시, 2 는 경고 표시(!!)가 붙는지, 3 은 세션 첫 응답 전 · /compact 직후에 필드가 null 일 때 죽지 않는지를 봅니다. 3 을 빼먹으면 세션을 켤 때마다 상태줄이 빈 줄로 나옵니다.

여기서 안 나오면 그것은 Claude Code 문제가 아니라 스크립트 문제입니다. 한글이 깨져 나오면 1 단계의 BOM 확인으로 돌아갑니다.

0 단계가 False 였다면(파일이 없거나 비어 있으면) 통째로 이렇게 적습니다.

%USERPROFILE%\.claude\settings.json — 새로 만들 때
{
  "statusLine": {
    "type": "command",
    "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:/Users/<사용자>/.claude/statusline.ps1\""
  }
}

0 단계가 True 였다면 기존 내용을 지우지 말고 최상위에 "statusLine" 키만 추가합니다. 앞의 키는 원래 있던 것이고 statusLine 만 붙는 모양입니다.

%USERPROFILE%\.claude\settings.json — 이미 있을 때
{
  "theme": "dark",
  "원래 있던 키": "…",
  "statusLine": {
    "type": "command",
    "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:/Users/<사용자>/.claude/statusline.ps1\""
  }
}
여기서 깨지는 세 가지
  • 쉼표 — 바로 앞 항목 끝에 , 를 붙여야 합니다.
  • 경로는 슬래시(/)로 — JSON 안에서 역슬래시는 두 번 적어야 하는 데다, Git Bash 가 깔린 PC 는 이 명령을 Git Bash 로 돌려 역슬래시가 한 번 더 먹힙니다. 슬래시로 적으면 두 문제를 다 피합니다. 경로를 감싼 따옴표는 JSON 안이므로 \" 로 적습니다.
  • 모양이 바뀐 따옴표 — 웹에서 긁어 오면 ” 같은 따옴표가 섞여 오고, 메모장은 그걸 그대로 저장합니다. 그러면 오류 메시지 없이 조용히 안 됩니다.

저장은 1 단계와 같습니다 — Ctrl+S. 다만 settings.json 은 BOM 없이 두는 편이 안전합니다(일부 JSON 파서가 BOM 에서 실패합니다). 확인과 교정은 이 두 줄입니다.

자리지금 값무엇을 정하는가바꿀 때 주의
① 변수 이름$tok내가 붙이는 이름. 아무 이름이나 됩니다세 줄 모두 같은 이름이어야 합니다. 하나만 바꾸면 빈칸으로 나옵니다

④ 형 변환[int]꺼낸 값을 정수로 읽으라는 지시소수점이 있으면 [double], 글자면 지웁니다. 숫자에 안 붙이면 계산에서 깨집니다
⑤ 출력 조각${tok} tok화면에 나오는 모양변수명 뒤에 글자가 바로 붙으면 중괄호가 필수입니다 — $tokTOK 는 통째로 변수명이 됩니다

그래서 0~3 을 손으로 칩니까, 붙여넣습니까

사실부터 말씀드리면 현장에서는 거의 전부 복사 · 붙여넣기입니다. 공식 문서의 예제를 긁어 붙이고 경로만 자기 것으로 바꾸는 것이 보통이고, 그게 게으른 것도 아닙니다 — JSON 블록이나 훅 골격은 외울 가치가 없는 ‘형식’이기 때문입니다. 손으로 치는 쪽이 더 정확하지도 않습니다 — 오타가 늘 뿐입니다.

다만 복사 · 붙여넣기가 깨지는 자리는 항상 같은 세 곳입니다.

  • 남의 경로 — /home/user/… 나 남의 사용자명이 박힌 경로. 이 가이드가 C:\Users\<사용자> 처럼 꺾쇠를 쓴 이유입니다.
  • 셸이 다름 — 인터넷 예제는 대부분 bash · jq 기준입니다. Windows 에 그대로 붙이면 돌아가지 않습니다. 이 가이드를 전부 PowerShell 로 쓴 이유입니다.
  • 인코딩과 따옴표 — 웹에서 긁어 오면 따옴표가 ” 같은 모양으로 바뀌어 오는 일이 있고, 메모장은 그걸 그대로 저장합니다. 그러면 오류 메시지 없이 조용히 안 됩니다.

그래서 권하는 방식은 한 줄로 “뼈대는 붙여넣고, 값은 손으로” 입니다. 괄호와 들여쓰기까지 그대로 옮겨 오되, 경로 · 이름 · 필드명은 직접 치십시오. 바로 앞 표의 굵은 다섯 자리가 정확히 ‘손으로 칠 곳’ 입니다.

Windows 기준이므로 PowerShell 판으로 적습니다. 아래는 설명용 예시가 아니라 2026-09-10 에 실제로 설치해 돌려 본 파일 전문입니다. used_percentage 와 remaining_percentage 를 함께 읽어 막대 · 사용률 · 잔량 을 한 줄로 냅니다.

%USERPROFILE%\.claude\statusline.ps1 · UTF-8(BOM)
# ─────────────────────────────────────────────────────────────
# Claude Code 상태줄 — 컨텍스트 사용률 / 잔량 · 비용 · 현재 폴더
# 위치 : %USERPROFILE%\.claude\statusline.ps1
# 주의 : 반드시 UTF-8(BOM) 으로 저장합니다. BOM 이 없으면
#        Windows PowerShell 5.1 이 ANSI 로 읽어 한글이 깨집니다.
# ─────────────────────────────────────────────────────────────

$ErrorActionPreference = 'SilentlyContinue'

# 출력은 UTF-8 로 고정 — 콘솔 코드페이지에 좌우되지 않게
[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding $false

# Claude Code 가 표준입력으로 세션 정보 JSON 을 넣어 줍니다
$j = [Console]::In.ReadToEnd() | ConvertFrom-Json

$model = $j.model.display_name
if (-not $model) { $model = 'claude' }

$dir = $j.workspace.current_dir
if ($dir) { $dir = Split-Path -Leaf $dir } else { $dir = '-' }

# ── 컨텍스트 사용률 / 잔량 ────────────────────────────────────
# 세션 첫 응답 전과 /compact 직후에는 null 일 수 있습니다. 기본값 필수.
$used = 0
if ($null -ne $j.context_window.used_percentage) {
    $used = [int][math]::Round([double]$j.context_window.used_percentage)
}

$left = 100 - $used
if ($null -ne $j.context_window.remaining_percentage) {
    $left = [int][math]::Round([double]$j.context_window.remaining_percentage)
}

# 10칸 막대 — 채워진 칸이 사용량
$fill = [int][math]::Round($used / 10.0)
if ($fill -lt 0)  { $fill = 0 }
if ($fill -gt 10) { $fill = 10 }
$bar = ('#' * $fill) + ('-' * (10 - $fill))

# 잔량이 얇아지면 눈에 띄게
$mark = ''
if ($left -lt 40) { $mark = ' !' }
if ($left -lt 20) { $mark = ' !!' }

# ── 비용 ──────────────────────────────────────────────────────
$cost = '{0:N2}' -f ([double]$j.cost.total_cost_usd)

"[$model] $dir | [$bar] 사용 $used% / 남음 $left%$mark | USD $cost"

이 스크립트에서 눈여겨볼 곳은 두 군데입니다.

줄왜 그렇게 썼는가
$left = 100 - $used 뒤에 다시 remaining_percentage 로 덮어쓰기두 필드는 둘 중 하나만 올 수도 있습니다. 사용률만 오면 100 에서 빼고, 잔량이 함께 오면 그 값을 그대로 믿습니다 — 계산보다 원본이 정확합니다
$used = 0 · $dir = '-' 같은 기본값세션 첫 응답 전과 /compact 직후에는 context_window 가 통째로 null 입니다. 기본값이 없으면 상태줄이 빈 줄로 나옵니다

그리고 %USERPROFILE%\.claude\settings.json 에 등록합니다 — 원래 있던 키는 건드리지 않고 statusLine 만 더합니다. 어느 창에 무엇을 치는가는 1.2 의 여섯 단계에 순서대로 있습니다. 저장하면 즉시 반영됩니다 — 재시작이 필요 없습니다. 직접 쓰지 않고 /statusline 을 실행해 원하는 모양을 말로 설명하면 AI 가 대신 만들어 줍니다.

시험 3 이 이 셋의 핵심입니다. null 이 들어와도 죽지 않는지를 설치 전에 확인해야 합니다 — 상태줄은 세션을 켤 때 가장 먼저 그려지고, 바로 그 시점이 필드가 null 인 시점입니다.

왜 잔량을 봐야 하는가

컨텍스트가 다 차면 자동으로 압축(compact) 이 일어나고, 압축은 세부를 뭉갭니다. 앞에서 분명히 정해 둔 경계 — 무엇을 기준으로 삼고 무엇은 건드리지 않는다 — 가 흐려지는 것이 정확히 이 지점입니다.

그래서 실무 규칙은 하나로 요약됩니다 — 잔량이 얇아지면 새 작업을 시작하지 말고, 결론부터 파일에 적습니다. 파일에 적힌 것은 압축돼도 남고, 대화에만 있던 것은 남지 않습니다.

1.4예시 B — “화면명 + 작업 완료” 를 매번 선언하지 않기

사람이 “demo_001 작업 완료” 라고 매번 적어 주는 대신, 턴이 끝날 때마다 자동으로 나오게 하는 것입니다. Stop 훅이 그 자리입니다 — AI 가 한 턴을 마칠 때 실행됩니다.

Stop 훅이 받는 JSON 에는 다음이 들어 있습니다(주요 필드만).

# 알리기만 한다. 어디서 끝나든 exit 0 — 작업을 세우지 않는다.

$since = (Get-Date).AddMinutes(-15)

$esc = [char]27
$bel = [char]7

@{
    hookSpecificOutput = @{
        hookEventName    = 'Stop'

훅을 쓸 때의 세 가지 원칙

1. 훅은 승인을 묻지 않고 실행됩니다. 그래서 훅에는 읽기 · 검사 · 알림만 둡니다. 파일 수정 · 커밋 · 푸시를 훅에 넣으면 사람이 보지 않는 사이에 저장소가 바뀝니다.

2. 실패해도 작업을 세우지 않게 합니다. 위 스크립트가 어디서 끝나든 exit 0 인 이유입니다. 종료 코드 2 만이 동작을 막습니다 — 막을 의도가 없으면 절대 2 로 끝내지 않습니다.

3. 느린 일은 뒤로 보냅니다. 훅 정의에 "async": true 를 주면 백그라운드에서 돌아가 턴을 붙잡지 않습니다.

1.6예시 D — 목록에 없는 함수는 쓰지도 못하게

실제 프로젝트에서 있었던 사고에 정확히 대응하는 장치입니다 — AI 가 목록에 없는 공통 함수를 그럴듯하게 지어내, 화면이 통째로 렌더되지 않았던 일입니다 (AI프로젝트 및 이력 탭의 연표). PreToolUse 훅만이 동작 자체를 막을 수 있습니다.

새 파일을 쓸 때(Write)는 content 에, 기존 파일을 고칠 때(Edit)는 new_string 에 새로 들어갈 내용이 들어옵니다. 둘을 이어 붙여 gfn 으로 시작하는 이름을 전부 뽑고, dataset\vocab.json 과 대조합니다.

.claude\hooks\deny-unlisted.ps1 · UTF-8(BOM)
# .claude\hooks\deny-unlisted.ps1 — PreToolUse 훅 : 카탈로그에 없는 gfn* 가 들어간 저장은 쓰기 전에 막는다
$ErrorActionPreference = 'SilentlyContinue'
[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding $false

$j    = [Console]::In.ReadToEnd() | ConvertFrom-Json
$proj = $env:CLAUDE_PROJECT_DIR
if (-not $proj) { $proj = $j.cwd }

$file = $j.tool_input.file_path
if ($file -notmatch '[\\/]screens[\\/]') { exit 0 }      # 판정 범위 — 10 회차에서 일부러 넓혀 오탐을 만들어 보는 자리

# 산출물에 등장한 공통 함수 이름을 전부 뽑는다 — Write 는 content, Edit 는 new_string
$text = "$($j.tool_input.content)$($j.tool_input.new_string)"
$used = [regex]::Matches($text, '\bgfn[A-Za-z0-9_]+') | ForEach-Object { $_.Value } | Sort-Object -Unique

# 카탈로그와 대조한다
$known   = @((Get-Content (Join-Path $proj 'dataset\vocab.json') -Raw -Encoding UTF8 | ConvertFrom-Json).functions)
$unknown = @($used | Where-Object { $known -notcontains $_ })

if ($unknown.Count -gt 0) {
    @{
        hookSpecificOutput = @{
            hookEventName            = 'PreToolUse'
            permissionDecision       = 'deny'
            permissionDecisionReason = "카탈로그 미등재 함수: $($unknown -join ', ') — dataset\vocab.json 을 먼저 확인하십시오."
        }
    } | ConvertTo-Json -Depth 5 -Compress
}
exit 0

다만 ③ 은 가장 늦게 붙여야 합니다. 오탐 하나가 작업을 세우기 때문입니다 — 목록이 불완전한 상태에서 차단부터 걸면 실재하는 함수를 못 쓰게 되는 반대편 사고가 납니다. 며칠은 'deny' 대신 'ask'(사람에게 묻기)로 돌려 오탐률을 잰 뒤 바꾸십시오. 도입 순서는 1.10 에 따로 적었습니다.

1.7예시 E — 세션이 시작될 때 오늘 자리를 알려주기

AI 는 세션이 끝나면 앞선 대화를 잊습니다. SessionStart 훅은 그에 대한 기계적 대응입니다 — 새 세션이 열릴 때마다 최근 일지와 진행 중인 화면을 자동으로 넣어 줍니다.

브라우저 자동화는 내 PC 에서 띄운 로컬 화면까지로 한정하는 것이 안전합니다. 운영 중인 시스템에 로그인시키는 자동화는 계정 · 개인정보 · 감사 로그 문제를 함께 끌고 옵니다.

받은 다섯 개를 어디에 두어야 하는가

MCP 서버와 플러그인은 폴더 위치가 아니라 ‘등록’ 으로 붙습니다. 그래서 어디에 두어도 동작합니다 — .claude\skills\ 안에 넣는다고 저절로 걸리지 않고, 바탕화면에 두었다고 안 걸리는 것도 아닙니다. 지켜야 할 것은 한 가지, 등록해 둔 경로를 그대로 두는 것입니다.

그러니 자리를 정하는 이유는 동작이 아니라 관리입니다. 프로젝트 폴더 바깥의 한 곳(이 가이드는 $libs)에 다섯 개를 나란히 두는 것을 권합니다. 프로젝트 안에 풀어 두면 검사기와 검색이 남의 저장소까지 훑어 컨텍스트를 잡아먹습니다.

예외가 하나 있습니다 — 스킬은 폴더 위치로 걸립니다. SKILL.md 가 든 폴더를 프로젝트의 .claude\skills\<스킬이름>\ 아래에 두면 등록도 명령도 없이 Claude 가 알아서 읽습니다. taste-skill 처럼 스킬 묶음으로 된 플러그인은 그 안의 스킬 폴더 하나만 꺼내 .claude\skills\ 에 복사해도 걸립니다 — 플러그인 전체가 필요하지는 않을 때 쓰는 방법입니다.

실측 — 2026-09-09 · 작성자 PC

사용자 settings.json 에 taste-skill 이 플러그인으로 등록돼 있고 활성 상태였습니다. 그런데 등록할 때는 taste-skill 이던 폴더 이름을, 나중에 보기 좋으라고 앞에 번호를 붙여 5.taste-skill 로 바꿨습니다.

설치본이 따로 복사돼 있어 쓰는 데는 문제가 없었지만, 갱신은 원본을 찾지 못해 조용히 실패하고 있었습니다. 경로를 고치거나 마켓플레이스를 다시 등록해야 풀립니다.

이 부 전체에 걸리는 교훈이기도 합니다 — 확장을 늘리면 확장 자체가 관리 대상이 됩니다. 훅 · MCP · 플러그인은 ‘한 번 붙이고 잊는 것’ 이 아니라 검사기와 같은 지위의 자산입니다.

1.10무엇부터 붙일 것인가

전부 한꺼번에 붙이면 무엇 때문에 무엇이 멈췄는지 알 수 없게 됩니다. 위험이 낮은 것부터 한 칸씩 올립니다.

1단계 — 위험 없음
상태줄

보기만 합니다. 잘못돼도 한 줄이 안 나올 뿐입니다. 컨텍스트 잔량 · 현재 폴더 · 비용을 걸어 두고 며칠 써 보면 어느 작업이 컨텍스트를 얼마나 차지하는지 감이 먼저 잡힙니다.

2단계 — 알림
Stop 훅 — 화면명 + 완료

알리기만 합니다. 여기서 훅의 입출력 규약(표준입력 JSON · hookSpecificOutput · 종료 코드)에 익숙해집니다. exit 0 을 지키는 한 작업을 세울 일이 없습니다.

3단계 — 검사
PostToolUse 훅 — 저장하면 검사

이미 있는 검사기를 자동으로 돌릴 뿐이라 새 판정 기준이 생기지 않습니다. 결과는 additionalContext 로 되돌려 AI 가 스스로 고치게 둡니다. 느리면 "async": true 를 줍니다.

4단계 — 주입
SessionStart 훅 — 오늘 자리

컨텍스트를 차지하는 장치라 여기서부터는 대가가 있습니다. 최근 일지 한 건과 화면 목록 정도로 짧게 유지하고, 길어지면 CLAUDE.md 와 같은 성격의 부담이 된다는 점을 기억합니다.

5단계 — 차단
PreToolUse 훅 — 미등재 함수 거부

맨 마지막입니다. 오탐 하나가 작업을 세웁니다. 목록이 실제로 완전한지 먼저 확인하고, 며칠은 deny 대신 ask 로 돌려 오탐률을 재고 나서 차단으로 바꿉니다.

이 순서의 원칙

보는 것 → 알리는 것 → 검사하는 것 → 주입하는 것 → 막는 것.

막는 것을 먼저 붙이면, 도구를 신뢰하기도 전에 도구가 작업을 세웁니다. 원 프로젝트가 다섯 달에 걸쳐 문서 → 표준 → 검사기 순서로 올라온 것과 같은 순서입니다 — AI프로젝트 및 이력 탭의 연표가 곧 이 사다리의 실물 사례입니다.

이 부의 훅 이름 · JSON 필드 · 설정 구조는 2026-09-10 에 Claude Code 공식 문서와 대조한 것입니다. Claude Code 는 갱신이 잦으므로, 붙이기 전에 /hooks 나 /status 로 현재 버전의 동작을 한 번 확인하시는 편이 좋습니다.

# scripts\check.ps1 — 카탈로그(dataset\vocab.json)에 없는 gfn* 함수를 찾아 줄 번호를 찍는다
# 사용 : powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check.ps1 [검사할 파일 또는 폴더]
# 종료 코드 : 0 = 통과, 1 = 위반 있음
param([string]$Path = 'screens')

$root  = Split-Path -Parent $PSScriptRoot                       # scripts\ 의 한 칸 위 = 프로젝트 최상위
$vocab = Get-Content (Join-Path $root 'dataset\vocab.json') -Raw -Encoding UTF8 | ConvertFrom-Json
$known = @($vocab.functions)

if (-not [IO.Path]::IsPathRooted($Path)) { $Path = Join-Path $root $Path }
if (-not (Test-Path $Path)) { "검사 대상 없음: $Path"; exit 0 }

$files = Get-ChildItem $Path -Recurse -File -Include *.html, *.js, *.md -ErrorAction SilentlyContinue
$bad = 0
foreach ($f in $files) {
    $n = 0
    foreach ($line in (Get-Content $f.FullName -Encoding UTF8)) {
        $n++
        foreach ($m in [regex]::Matches($line, '\bgfn[A-Za-z0-9_]+')) {
            if ($known -notcontains $m.Value) {
                "위반  $($f.Name):$n  $($m.Value) — 카탈로그에 없음"
                $bad++
            }
        }
    }
}

if ($bad -eq 0) { "통과 — 파일 $($files.Count)개, 미등재 함수 0건"; exit 0 }
"위반 $bad 건"
exit 1
